# Deploying Project Camp

| Part | Service | Config in this repo |
|---|---|---|
| Database | MongoDB Atlas (free M0) | none; you create the cluster |
| API (`backend/`) | Render web service (free) | `render.yaml` |
| App (`frontend/`) | Vercel | `frontend/vercel.json`, `frontend/.env.production` |

**How the pieces connect.** The browser only ever talks to the Vercel domain. Vercel forwards `/api/*` to the Render API, so the login cookies are first-party and work in every browser, Safari included. Every other path serves the single-page app, so reloading a deep link such as `/dashboard/projects/<id>/board` works.

## 1. MongoDB Atlas

1. On cloud.mongodb.com, create a free **M0** cluster.
2. Under **Database Access**, add a database user with a strong password.
3. Under **Network Access**, allow `0.0.0.0/0`. Render's free plan has no fixed outbound IP.
4. Under **Connect → Drivers**, copy the connection string. Add a database name before the `?`, for example:
   `mongodb+srv://<user>:<password>@<cluster>.mongodb.net/projectcamp?retryWrites=true&w=majority`

## 2. Render (API)

1. Go to dashboard.render.com, then **New → Blueprint**, and pick this GitHub repo. Render reads `render.yaml`.
2. Fill in the values it asks for:
   - `MONGO_URL`: the Atlas string from step 1.
   - `CORS_ORIGIN`: your Vercel URL, for example `https://project-camp.vercel.app`. If you don't know it yet, enter a placeholder and update it after step 3.
   - `FORGOT_PASSWORD_REDIRECT_URL`: `https://<your-vercel-domain>/auth/reset-password`
   - `EMAIL_VERIFICATION_REDIRECT_URL`: `https://<your-vercel-domain>/auth/verify-email`
   - The `MAIL_TRAP_*` values are optional. Leave them empty and the app still works, but emails aren't sent and accounts stay "unverified" (which doesn't block sign-in).
3. After the deploy, open `https://<service>.onrender.com/api/v1/healthcheck/ready`. It should answer 200.
4. If Render gave the service a different URL from `https://project-camp-api.onrender.com`, update the `destination` in `frontend/vercel.json` and push.

Swagger UI (`/api-docs`) is disabled in production. Set `ENABLE_API_DOCS=true` on the Render service only if you want it public.

The access and refresh token secrets are generated by Render. `TRUST_PROXY=2` is set because requests pass through Vercel and then Render's load balancer.

**Free plan:** the API sleeps after about 15 minutes idle, and the first request after that takes around 50 seconds. Before a client demo, open the app once a minute ahead.

## 3. Vercel (app)

1. Go to vercel.com, then **Add New → Project**, and import this GitHub repo.
2. Set **Root Directory** to `frontend`. The framework (Vite), build command and output are picked up from `vercel.json`.
3. No environment variables are needed, because `frontend/.env.production` sets `VITE_API_BASE_URL=/api/v1`.
4. Deploy. Then put the final Vercel URL into Render's `CORS_ORIGIN` and the two redirect URLs, and redeploy the API.

## 4. Load the demo team (optional)

From your machine, run this against the Render URL directly:

```bash
cd backend
API_URL=https://<service>.onrender.com npm run seed:demo
```

It creates the six accounts in `docs/DEMO_GUIDE.md` (password `DemoPass123`), and skips if they already exist. Unlike the local demo, this data is permanent.

## 5. Check it

- Sign up, sign in, reload a deep link, then sign out.
- Sign in as `priya@demo.dev` and walk through `docs/DEMO_GUIDE.md`.
- In the browser devtools, Network tab, every request should go to the Vercel domain, and none to `onrender.com`.
